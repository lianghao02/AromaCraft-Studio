# 安裝與家庭帳號部署

## 1. 建立資料試算表

以維護者 Google 帳號建立一份全新的 Google 試算表，命名「AromaCraft Studio 家庭資料」。從網址 `/spreadsheets/d/` 後到下一個 `/` 前取得試算表 ID。請勿把 ID、家人 Email、憑證或登入資料寫入 Git。

Google 試算表「共用」設定為「受限制」，只加入家庭成員個別 Google 帳號，授予編輯者權限。不要開啟「知道連結的任何人」或發布到網路。此權限是以存取者身分執行的必要條件。

## 2. 建立獨立 Apps Script 專案

1. 開啟 [Apps Script](https://script.google.com/)，以維護者帳號建立獨立新專案，命名 AromaCraft-Studio。不要使用試算表綁定專案，避免所有試算表編輯者同時取得程式編輯能力。
2. 將 `src/Code.gs` 全部貼入預設的 `Code.gs`。
3. 新增 HTML 檔案，分別命名 `Index`、`Styles`、`Core`、`Client`，貼入對應 `.html` 的完整內容。Google 編輯器會自行顯示副檔名，名稱不要重複加 `.html`。
4. 進入「專案設定」，勾選「在編輯器中顯示 appsscript.json 資訊清單檔案」，將 `src/appsscript.json` 完整貼入。
5. 設定專案時區為 Asia/Taipei。不要把 `tools/`、`tests/` 或 `package.json` 貼到 Apps Script。

## 3. 設定指令碼屬性

在「專案設定 → 指令碼屬性」新增以下 3 項，值由你自己填寫：

| 屬性名稱 | 值 |
|---|---|
| `SPREADSHEET_ID` | 第 1 步取得的試算表 ID，僅填 ID |
| `ADMIN_EMAIL` | 維護者 Google 帳號的完整 Email |
| `ALLOWED_EMAILS` | 所有允許的家庭帳號，以半形逗號分隔，必須包含維護者 |

白名單需填入登入後 Google 實際回報的帳號，不能以顯示名稱替代。登入帳號的別名不一定與回傳 Email 相同，若被拒絕請確認實際帳號。設定值會去除前後空白並轉為小寫比對。

## 4. 初始化八張工作表

在 Apps Script 上方函式清單選擇 `setupDatabase` 並執行，由維護者完成 Google 授權。授權範圍為試算表與使用者 Email；不要求 Gmail 或 Drive 檔案權限。請確認官方 Google 畫面顯示的專案、帳號及範圍，只對自己建立且已檢查的程式授權；若被組織管理政策或安全驗證阻擋，停止並依 Google／組織核准流程處理。

初始化建立：原料資料、原料價格、配方資料、配方明細、安全規則、製作紀錄、成本設定、系統設定。既有表頭不相容時停止，不清空任何原始表。可重跑，已存在資料不重複建立。

新的試算表可能保留預設「工作表1」。程式保留它，避免自動刪除資料；確認它完全空白後，手動刪除此預設工作表，資料庫便只有上述 8 張表。

示範原料附零元價格，只供成本操作試算。安全規則表保持空白，不附虛構濃度上限。

## 5. 發布 Web App

1. 選擇「部署 → 新增部署 → 類型：網頁應用程式」。
2. **執行身分選擇「存取網頁應用程式的使用者」**；資訊清單對應 `USER_ACCESSING`。
3. 存取者選擇可要求 Google 登入的「任何擁有 Google 帳戶的使用者」（資訊清單為 `ANYONE`）。如果組織只提供「網域內使用者」，家人必須在可存取的網域內。
4. 不要選「任何人（含匿名）」／`ANYONE_ANONYMOUS`。不要以「我」／`USER_DEPLOYING` 作為跨帳號家庭部署方式。
5. 部署後取得結尾為 `/exec` 的網址，僅提供給家人。家人第一次開啟時，以白名單中的 Google 帳號完成授權，並確認包含試算表與 Email 範圍。
6. 程式修改後，至「管理部署 → 編輯 → 新版本」更新部署。編輯器儲存程式不會自動更新既有 `/exec` 部署。

`/dev` 是開發測試網址，僅供具有程式編輯權限者使用，不用作家庭正式網址。正式 Web App 本身仍需下列驗收，網址保密不能替代帳號檢查。

## 6. 正式使用前驗收

- [ ] 維護者帳號可讀取八表，保存一份測試配方並讀回。
- [ ] 第二位家庭白名單帳號在另一裝置登入、授權，可讀取並另存新版。
- [ ] 不在白名單的 Google 帳號只能看見存取限制，不能讀取原料、成本、配方、紀錄或匯出。
- [ ] 未登入、拒絕必要授權、無試算表編輯權限時被拒絕，不能取得家庭資料。
- [ ] 兩裝置同時載入一版，一方另存新版後另一方儲存時出現版本衝突，草稿保留。
- [ ] 更新採購批次後，既有配方價格不自動換批次，製作快照保持原數值。
- [ ] iPhone Safari／Android Chrome 可加入原料、調整、儲存與讀回，底部按鈕不被系統安全區遮住。

**未通過帳號隔離驗收，不能宣稱家庭存取限制已確保。** 若 Google 無法可靠回報帳號，系統會拒絕。若帳號／Workspace 政策不支援此組合，將部署限制為僅本人，暫停家庭共用，不能為了讓家人進入而改成匿名存取。程式不提供可繞過授權的降級模式。

## 7. 日常操作、備份與復原

原料卡「管理」可改名稱、分類、備註及啟用狀態；「新價格」建立不可覆寫的採購批次。配方儲存時，所有價格必須有 g 重量換算；mL 必填該原料密度，瓶／包／盒必填每單位重量。填入價格後需於配方卡選擇此批次。

若儲存出現連線失敗，保留頁面，按「重新讀取雲端」檢查是否已出現該版本；同一未修改草稿直接再按儲存，會沿用請求識別碼，避免重複版本。如果重新整理整頁，先按「恢復本機草稿」並重新讀取最新版本後確認。不要在連線不確定時反覆建立新的製作紀錄。

每次重要修改前，可在網頁按「匯出備份」下載 8 張表與目前草稿的 JSON。iPhone Safari 若呈現分享／下載預覽，請存至「檔案」。此檔可檢查及離線保存，但第一版沒有自動匯入。

完整備份：Google 試算表選「檔案 → 建立副本」，保存在自己的雲端硬碟，確認副本沒有額外共享或公開發布。另保存 Apps Script 原始碼與指令碼屬性設定於私人位置。

復原：先停用家庭部署，保存目前出錯試算表的副本；確認備份的 8 張表及欄位正確，再將 `SPREADSHEET_ID` 指向備份副本、重新共享給家庭成員並完成第 6 步驗收。不可把 JSON 直接貼入資料表當作復原操作。

## 8. 常見錯誤

| 提示 | 處理 |
|---|---|
| `AUTH` | 檢查目前 Google 帳號、白名單、管理員設定及部署執行身分；空白身分不能放行 |
| `ACCESS` | 檢查試算表 ID、受限制共享中的編輯權限、必要授權 |
| `SETUP`／`SCHEMA` | 由維護者確認初始化及八表表頭；不要清空原始資料 |
| `CONFLICT` | 保留草稿，複製成新配方或載入最新版本再編輯 |
| `BUSY` | 其他家人正在讀寫，稍後重試 |
| 密度／重量未填 | 補上該採購品的可靠換算資料，不能用其他精油的密度代替 |
