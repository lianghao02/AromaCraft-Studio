# 單位換算與總量規則

更新日期：2026-10-13。前後端共用 Core.html，後端重新計算，不相信用戶端傳來的成本、密度或合計值。

## 使用方式

1. 每份配方選 g（重量）或 mL（投入體積）作總量基準。按摩油、日常清潔、水垢清潔空白範本預設 mL；肥皂、香膏預設 g。
2. 點原料卡，選一種輸入單位：g、mL、整數滴數或百分比。切換單位有足夠資料時保留實量；資料不足時清空尚未套用的輸入並提示，原配方不變。非整滴不自動四捨五入。
3. % 必須先勾固定總量、填入總量。自由總量由各項實際用量合計，比例只反算，不猜測分母。
4. 指定補足原料後，其用量等於固定總量減其他項目合計。其他項目超量會拒絕；不能直接改補足原料破壞總量。
5. 未補足的固定總量、缺換算值或無效用量會停用儲存；後端也會拒絕。設定總量即時計算，不等到儲存才發現。
6. 取消固定總量時將 % 轉回當時實量，清除補足設定。切換總量基準保留實量且清除舊固定總量；跨重量／體積仍需各項密度。
7. 等比例縮放使用新總量÷原總量，結果以配方基準單位保存，不把小數用量偷偷變成整滴。

## 換算與成本

- g＝mL×該價格批次密度；mL＝g÷密度。
- mL＝滴數÷該價格批次每 mL 滴數。
- 百分比的實量＝固定總量×比例÷100；顯示百分比＝基準用量÷實際合計×100。
- 材料成本＝基準用量×所選採購批次的每基準單位價格；包材按成品份數另計。
- mL 購入、mL 使用不需要密度。mL 購入要按 g 計費，或 g 購入按 mL 使用，才需要密度。
- 不預設 1 mL＝1 g 或通用滴數。密度與滴數設定在新增採購批次，舊批次與舊快照不覆寫。
- 重量 % 與體積 % 不混用。舊安全規則缺 basis 時按既有重量規則處理；體積配方不套用這些規則。安全狀態仍保持待驗證。
- mL 合計是投入的名義體積估算，不保證混合後量測體積完全相等；配比與成本不是製作安全認證。

## 官網精油

管理員在「設定與資料」先升級單位欄位，再按「載入內建官網價格」（開啟網頁時也會自動補入缺少的項目；此功能不會連線官網，價格以內建快照日期為準，目前為 2026-10-13）。只匯入有明確容量與價格的單方／配方精油，不將套組、滾珠或按摩成品自動當純精油；另匯入 V-6 綜合純植物油（236 mL、944 mL 補充裝）作為「基底油」類別。此版資料有 94 筆精油規格與 2 筆 V-6；重跑不重複，不修改既有配方價格。匯入的是含稅未含運費的官網批發估算，密度和滴數保持空白。正式採購不同時建立實際價格批次。

本機預覽使用記憶體資料並自動導入目錄；不連線 Google。舊的獨立目錄試算仍保留供查價，但現在原料庫可直接把官網 mL 精油加入主配方及保存。

## 資料相容與升級

維持八張工作表，只在末端追加欄位：

| 工作表 | 新增欄位 |
|---|---|
| 原料價格 | dropsPerMl |
| 配方資料 | quantityUnit、targetQuantity |
| 配方明細 | quantity、unit |
| 安全規則 | basis |

管理員按「升級單位欄位」或在 Apps Script 執行 migrateUnitSchema。先建立試算表副本備份，再升級。遷移先查核所有預期欄位位置，遇到其他表頭或未命名欄位下已有資料就中止；只追加表頭，不覆寫舊儲存格或快照，可以重跑。沒有新增欄位的舊 g 配方仍可讀取；新式單位資料保存前須升級。

原始 quantity／unit、配方總量基準與固定總量會保存。快照保留換算後實量、比例、該批次密度／滴數與成本。製作紀錄依該版本快照計費，不以最新換算值回算。

部署需更新 src 全部八檔，其中 Catalog.html 是目錄介面，CatalogData.html 是供後端讀取的 JSON。不要把 CatalogData.html 當作畫面貼入 Index。既有六檔加上這兩份 HTML 檔，再更新正式部署版本。此輪未更新真實 Google 部署／工作表。
