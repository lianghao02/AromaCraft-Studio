# AromaCraft 介面重新設計規格（草案 v0.1）

> 狀態：草案，待使用者確認後才動手實作。分支：`redesign-v2`（由 main v1.6.5 分出）。
> 範圍：只重做「畫面層與操作流程」。計算、單位換算、同步、儲存、Firebase 規則、價格快照一律沿用，不重寫。

## 1. 設計目標

| 目標 | 具體做法 |
|---|---|
| 清楚的框框 | 一個畫面只有一層框；不再有摺疊面板包摺疊面板 |
| 清楚的文字 | 內文最小 14px、輔助文字最小 12px；同一動作只用一個詞 |
| 流程明瞭順暢 | 一次只顯示一個步驟；選原料與填用量合併為同一步 |
| 不必要的減少 | 平常用不到的功能移出主流程（見第 7 節移除清單） |
| 手機優先 | 以 390px 寬為基準設計，再向平板、桌機延伸 |

## 2. 資訊架構

```
底部／頂部頁籤（3 個，維持現狀）
├─ 調配方   ← 主流程（3 步）
├─ 配方庫   ← 已儲存配方、開始製作、製作紀錄
└─ 設定     ← 原料與價格、包材、雲端同步、資料與維護、說明
```

調整：「製作紀錄」併入「配方庫」（每個配方可展開看它的紀錄），設定頁只留準備類項目。

## 3. 邏輯規格（狀態機）

### 3.1 配方草稿狀態

```
draft = {
  type,              // 精油膏｜清潔劑｜精油皂｜按摩油｜其他
  name, units,       // 名稱、份數（正整數）
  items[],           // { materialId, quantity, unit }（沿用現有結構）
  packageId | null,  // 整套包材或不使用
  target | null,     // 目標總量（選填）
  notes,
  source: new | saved(id) | production(id)
}
```

草稿只留本機（沿用現有 `draft()` 機制），按「儲存」才進入同步佇列。

### 3.2 步驟與轉換

| 步驟 | 進入條件 | 離開條件 | 主按鈕 | 回上一步 |
|---|---|---|---|---|
| 1 類別 | 新配方；或載入舊配方時略過 | 點選一個類別 | （點類別即自動進入步驟 2） | — |
| 2 原料與用量 | 已有類別 | 至少 1 項原料且用量 > 0 | 下一步 → 確認 | 返回步驟 1，已選原料保留 |
| 3 確認 | 步驟 2 計算成功 | 儲存或完成製作 | 儲存配方 | 返回步驟 2，內容保留 |

規則：
- 換類別時，已選原料與用量保留（沿用現有行為）。
- 載入舊配方（從配方庫）直接進入步驟 3，可從步驟 3 回步驟 2 修改。
- 計算失敗（缺價格、缺密度、單位不合）不阻擋進入步驟 3，沿用現有 `calculate()` 的缺項顯示：列出已知費用與缺哪些項。
- 離開頁面或切換頁籤，草稿自動保留；回來時顯示「繼續上次的配方」。

### 3.3 步驟 2 內的列狀態

每個原料列只有三種狀態：

```
未選 ──點「加入」──▶ 已選（展開用量輸入）──點「移除」──▶ 未選（出現「復原」提示）
```

- 加入後預設單位：精油用「滴」，基底油與其他用採購單位（沿用 `applyDropDefaults`、`availableUnits`）。
- 單位只列出可換算的選項；缺密度時不提供 g↔mL 互換（沿用現有規則）。
- 用量輸入使用 − / + 加數字框；滴數步進 1，g／mL 步進依量級自動調整。

### 3.4 儲存與完成製作

| 動作 | 行為 | 出現時機 |
|---|---|---|
| 儲存配方 | 新配方：建立；舊配方：更新同一筆 | 一律顯示（主按鈕） |
| 另存為新配方 | 建立新的一筆，原配方不變 | 僅編輯舊配方時顯示 |
| 完成製作 | 凍結當次用量、日期、份數、價格，原配方不變 | 僅從配方庫「開始製作」進入時顯示 |

「開始製作」只放在配方庫，不再出現在調配畫面的摺疊區。

### 3.5 沿用的核心函式（不改）

`Core.calculate`、`convertInput`、`availableUnits`、`applyDropDefaults`、`automaticConcentration`、`scaleRecipe`、`balance`，以及 `Code.gs` 與同步／離線佇列。新畫面只呼叫它們，不複製邏輯。

## 4. 手機版畫面（390px 基準）

### 4.0 共用框架

```
┌──────────────────────────┐
│ 🌿 AromaCraft      ☁ 本機 ?│  ← 單行；標題縮成圖示＋名稱，狀態與說明收成兩個小圖示
├──────────────────────────┤
│ ① 類別 ─ ② 原料 ─ ③ 確認   │  ← 進度條，已完成的可點回
├──────────────────────────┤
│        （步驟內容）         │
├──────────────────────────┤
│ 底部固定列（步驟 2、3 才有） │
├──────────────────────────┤
│  調配方   配方庫   設定     │  ← 底部頁籤
└──────────────────────────┘
```

### 4.1 步驟 1：做什麼？

```
你要做什麼？
┌────────┐ ┌────────┐
│ 精油膏  │ │ 清潔劑  │
└────────┘ └────────┘
┌────────┐ ┌────────┐
│ 精油皂  │ │ 按摩油  │
└────────┘ └────────┘
┌──────────────────┐
│ 其他              │
└──────────────────┘
```
- 每個類別為大按鈕（高 64px 以上），點一下直接進入步驟 2。
- 各類別下方一行小字顯示範本的基底提示（來自 `work-templates.json` 的 `base`）。
- 本頁不放「清空」「新增自製配方」；「新增自製配方」併入類別「其他」。

### 4.2 步驟 2：加原料、填用量

```
精油膏 ▸ 更換
搜尋 [__________]
[ 精油 ][ 基底油 ][ 蜂蠟 ][ 全部 ]   ← 預設分頁依類別決定

已選（2）
┌──────────────────────────┐
│ 薰衣草          NT$12／滴  │
│ [−]  10  [+]   滴 ▾        │
│                    移除    │
└──────────────────────────┘
原料
┌──────────────────────────┐
│ 甜杏仁油    NT$4／mL  [加入]│
└──────────────────────────┘
……（每次 8 筆，「再顯示 8 筆」）
━━━━━━━━━━━━━━━━━━━━━━━━
 3 項 ・ 約 $86 ・ 濃度 2.1%    [下一步]
```
- 已選區固定在原料列表上方，只有選了才出現。
- 預設分頁：精油膏＝精油；按摩油＝基底油；精油皂＝皂基；清潔劑與其他＝全部。
- 底部固定列：項數、目前成本、精油濃度（有精油時才出現）、主按鈕。
- 沒選精油時不顯示濃度；缺價格時成本顯示「已知 $xx，缺 n 項」。
- 「自由填量／依目標調配」不放在此步；移到步驟 3 的「目標總量」。

### 4.3 步驟 3：確認並儲存

```
名稱 [____________]
份數 [−] 4 [+]      包材 [不使用 ▾]
┌────────────┬────────────┐
│ 總成本       │ 每份成本     │
│ $86         │ $21.5       │
└────────────┴────────────┘
精油濃度 2.1%（估算）
原料明細
  薰衣草     10 滴    $12
  甜杏仁油   30 mL    $120
  …
▸ 目標總量（選填）
▸ 備註
─────────────
[   儲存配方   ]   ← 主按鈕（實心）
```
- 原料明細直接列出，不摺疊。
- 「目標總量」「備註」為僅有的兩個折疊項，且折疊內不再有折疊。
- 超過目標總量仍可儲存，顯示提醒（沿用現有規則）。
- 安全提示一行常駐：「濃度僅供參考，使用前請確認成分與用途」。

### 4.4 配方庫

```
搜尋 [______]  類別 [全部 ▾]
┌──────────────────────────┐
│ 薰衣草舒緩膏        精油膏 │
│ 2.1% ・ 每份 $21.5 ・ 10/22 │
│ [開始製作]   [編輯]   ⋯   │
└──────────────────────────┘
```
- 點整張卡片＝編輯（進入步驟 3）；「開始製作」為次要按鈕；「複製」「移除」收在 ⋯ 選單。
- 每張卡片可展開看該配方的製作紀錄。

### 4.5 設定

分區改為清單入口，一次只進入一項：

```
原料與價格 ›
包材 ›
雲端同步 ›
資料與備份 ›
價格更新（進階） ›
使用說明 ›
```
「首次安裝與資料更新」「複製提示詞」「升級單位欄位」等維護項放進「資料與備份」，平常不出現。

## 5. 網頁版畫面（≥ 1024px）

### 5.1 版面

```
┌──────────────────────────────────────────────┐
│ 🌿 AromaCraft     調配方｜配方庫｜設定     ☁ 本機  ? │  ← 頂部單列
├────────────────────────┬─────────────────────┤
│ ① 類別 ─ ② 原料 ─ ③ 確認 │                     │
│                        │  配方與成本（固定）   │
│  左：目前步驟內容       │  已選原料、總成本、   │
│  （原料列表為 2 欄）    │  每份成本、濃度       │
│                        │  [儲存配方]           │
└────────────────────────┴─────────────────────┘
```
- 內容最大寬度 1200px，置中，不再拉滿螢幕。
- 右側「配方與成本」欄固定顯示（桌機沒有底部固定列），步驟 3 時右欄就是確認內容，左欄放名稱、份數、包材、目標總量與備註。
- 步驟 1 在桌機只佔左欄上方一排，選完不佔高度。
- 原料列表 2 欄（每次 12 筆），搜尋與分頁在列表上方。

### 5.2 平板（600–1023px）

沿用手機的單欄版面，內容最大寬度 720px 置中，底部列改為頁面底部固定。

### 5.3 斷點

| 寬度 | 版面 |
|---|---|
| < 600 | 手機：單欄、底部頁籤、底部固定列 |
| 600–1023 | 平板：單欄、置中、頂部頁籤 |
| ≥ 1024 | 桌機：左右兩欄、頂部頁籤、右欄固定 |

## 6. 視覺與文字規則

沿用木質 Q 版風格，但收斂：

| 元件 | 規則 |
|---|---|
| 主按鈕 | 每畫面只有一個；實心綠色＋下沉陰影 |
| 次要按鈕 | 細邊框、無陰影 |
| 卡片／輸入框 | 一層細邊框；不使用粗邊框＋底部陰影 |
| 危險動作 | 紅字細邊框；一律先跳確認視窗，並提供「復原」 |
| 字級 | 內文 14–16px；輔助 12px（不得更小）；標題 18–22px |
| 點擊區 | 最小 44×44px（沿用） |
| 顏色 | 步驟三色（橘／紫／綠）改為進度條使用，內容區統一底色 |

用詞固定（同一動作只用一個詞）：

| 動作 | 固定用詞 | 取代 |
|---|---|---|
| 存配方 | 儲存配方 | 另存配方、保存 |
| 存成新的一筆 | 另存為新配方 | 複製成新配方 |
| 回上一步 | 返回上一步 | 返回繼續編輯、返回第 2 步調整、返回原配方 |
| 清掉重來 | 重新開始（僅一處） | 清空精油試算、清空目前原料、清空目前內容 |
| 開始實作 | 開始製作／完成製作 | — |

## 7. 移除與搬移清單

| 現有項目 | 處理 |
|---|---|
| 步驟 2 的「進階：調配方式」 | 移到步驟 3「目標總量」 |
| 步驟 2 的「悠樂芳精油目錄與成本試算」 | 移到設定 › 價格更新 |
| 步驟 2 的濃度藍色面板（空狀態） | 刪除；改為底部固定列一行 |
| 「先勾選、再集中填量」兩段式 | 合併為單列加入＋填量 |
| 步驟 3 的「查看各項用量」折疊 | 直接顯示 |
| 步驟 3 的「實際製作與紀錄」折疊 | 移到配方庫 |
| 步驟 3 的「製作備註與工具」折疊 | 只留「備註」 |
| 三個「清空」按鈕 | 合併為一處「重新開始」 |
| 「恢復頂部 3 步新手指南」 | 改為進度條常駐，不需要指南 |
| 「新增自製配方」整條按鈕 | 併入類別「其他」 |
| 設定頁「製作紀錄」 | 併入配方庫 |

## 8. 不改動的項目

計算與單位規則、估算密度標示、成本缺項顯示、Firebase 同步與離線佇列、刪除標記、Firestore 規則、價格快照與更新工具、Service Worker 快取規則、既有已儲存資料格式。

## 9. 驗收方式

1. 核心測試（`core`、`units`、`planning`、`cloud`、`catalog*`、`server` 等）維持全數通過，不修改。
2. 與舊畫面結構綁定的測試（`dom-contract`、`client`、`standalone`）依新結構改寫，並補：步驟轉換、列狀態、底部固定列、換類別保留原料。
3. Chromium 在 390、820、1366 三種寬度各截圖：三個步驟、配方庫、設定，逐張比對本規格。
4. 手機實機（iPhone）觸控與已安裝 PWA 更新，由使用者人工驗收，不以模擬代替。
5. 舊配方資料載入後計算結果與 v1.6.5 逐筆一致。

## 10. 待使用者決定

1. 步驟 1 點類別後是否自動進入步驟 2（本規格預設：自動）。
2. 「完成製作」實際是否常用；不常用則可從配方庫移到次層。
3. 成本設定（耗損、工時、時薪、毛利、售價）現有欄位是否保留；本規格預設收進步驟 3 的一個「進階成本」折疊，需先核對現有畫面實際露出哪些欄位。
4. 桌機是否需要兩欄固定右側成本，或維持單欄（本規格預設：兩欄）。
5. 新版在合併前是否要部署到預覽網址讓家人試用。
