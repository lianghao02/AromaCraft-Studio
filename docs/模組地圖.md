# 模組地圖（給接手的人與 Agent）

> 先讀這份再動手：知道每個檔案管什麼、改哪一類功能要跑哪些測試、有哪些已踩過的坑。

## 檔案分工（手寫來源都在 `src/`）
| 檔案 | 管什麼 | 備註 |
|---|---|---|
| `src/Core.html` | 計算：單位換算、濃度、成本、安全規則判定 | **前後端共用**（網頁與 `Code.gs` 都載入同一份）。純函式、測試最完整；改這裡影響最大 |
| `src/Code.gs` | 伺服器端 API：存取驗證、資料表讀寫、匯入、重算驗證 | 每個入口都由 `api()` 先驗證身分；Apps Script 獨立部署用 |
| `src/Client.html` | 畫面行為：渲染、事件、草稿、離線佇列互動（單一閉包、共用可變狀態） | 全專案最大的手寫檔（約 83KB）；內部分區見下方 |
| `src/Index.html` | 頁面骨架與元素 id；用 `include_('名稱')` 組入其他檔 | 元素 id 是 Client 的契約，見 `tests/dom-contract.test.cjs` |
| `src/Styles.html` | 全部樣式（Q 版風格、手機／桌機版面、手感規則） | 檔尾是較新的覆蓋規則（原料卡精簡、手感、提示詞對話框） |
| `src/Catalog.html`、`src/CatalogData.html` | 官網價格快照的目錄邏輯與資料 | **由 `data/young-living-tw.json` 產生**，不手改；用 `tools/refresh-catalog.cjs` 更新，見 `docs/官網價格更新.md` |
| `tools/standalone-provider.js` | 靜態網頁版的瀏覽器儲存、Firebase 家庭雲端同步 | 與 `Code.gs` 共用同一份後端邏輯 |
| `index.html`（根目錄） | **建置產物**，GitHub Pages 發布用 | **絕對不要手改**：改 `src/` 後執行 `npm run build` 重新產生 |

## 組裝方式
`src/Index.html` 以 `<?!= include_('Styles'); ?>`、`Core`、`Catalog`、`Client` 組入各檔。`tools/build-standalone.cjs` 對任何 `include_('名稱')` 都會讀入 `src/名稱.html`，所以新增來源檔只需要：
1. 在 `src/Index.html` 加一行 `include_`（順序即載入順序，使用傳統 `<script>`，不用 ES Modules）。
2. 把檔名加進 `tools/check.cjs` 的語法檢查清單。
3. 讀取 `Client.html` 的測試（`client.test.cjs`、`catalog-auto.test.cjs`、`prompt.test.cjs`）要改成依序載入所有拆出的檔。
4. Apps Script 獨立部署需另外上傳新的 HTML 檔。

## `Client.html` 內部分區（頂層函式依序）
狀態與工具（`$`、`money`、`fmt`、`escape`、草稿儲存）→ 狀態更新與渲染（`updateState`、`renderRecipe`、`calculate`）→ 原料清單（`renderMaterials`、`addSelection`、搜尋別名與排序）→ 配方庫（`renderSaved`）→ 對話框（`editItem`、`editMaterial`、`openEditor`）→ 填量流程（`renderSelected`、`nextQuantity`、手感腳本）→ 調配方式（`renderPlanner`、`changeTotal`）→ 製作（`beginProduction`、`finishProduction`）→ 事件綁定（檔案後段）。其中**約 40 個函式共用同一組可變狀態**（`data`、`recipe`、`dirty`、`busy`、`quantityMode`⋯），不是獨立模組。

## 改哪一類功能 → 要跑哪些測試
| 改動 | 必跑 |
|---|---|
| `Core.html` 計算、單位、濃度 | `core`、`units`、`planning`、`server`、`client`（`npm test` 全跑最保險） |
| `Code.gs` API、匯入、驗證 | `server`、`units`、`cloud`、`catalog-auto` |
| `Client.html`／`Index.html` 畫面 | `client`、`dom-contract`、`prompt`、`catalog-auto` |
| 官網價格資料、更新工具 | `catalog`、`refresh-catalog`、`standalone`、`prompt` |
| 升版 | `bump-version`（用 `node tools/bump-version.cjs`，不要手改四個地方） |
完成前一律 `npm run build`、`npm test`、`npm run check`，並確認 `git status` 沒有誤改 `index.html` 以外的產物。

## 已踩過的坑
- **假 DOM 會掩蓋缺元素**：`client.test.cjs` 的節點會自動建立，Client 引用了真實頁面沒有的 id 時測試不會失敗。`tests/dom-contract.test.cjs` 專門檢查；新增元素引用時，先把元素加進 `Index.html`。
- **跑測試會改到 `index.html`**：`cloud`、`standalone` 測試會呼叫 `build()` 重建產物，種子資料的時間戳與 UUID 會變。若沒有改 `src/`，這只是雜訊：用 `git checkout -- index.html` 還原，不要提交。
- **換行是 CRLF**：用腳本替換多行字串時要依檔案實際換行處理，否則找不到目標。
- **首次載入發生在 `busy` 狀態內**：啟動時的動作（例如自動匯入官網價格）不可加 `busy` 條件，否則永遠不會執行。
- **自動匯入與雲端同步**：只有透過 `rpc('importCatalog')` 的匯入會進 outbox 同步到家庭雲端；啟動時的本機匯入不會。
- **預覽要重啟**：`npm run preview` 啟動後讀入檔案，改了 `src/` 要重啟。預覽面板在背景時 CSS transition 不前進，量尺寸前先暫時關閉 transition。
- **hover 與觸控**：hover 規則只放在 `@media(hover:hover)` 內，否則 iPhone 會黏住；按下回饋用 `:active`。
- **部署要明確授權**：提交與推送到 main 會自動部署 GitHub Pages，沒有使用者明確授權不要推送。

## 拆分準則（不為行數而拆）
- 目前**不拆** `Client.html`：可抽的純函式只有 `money`／`fmt`／`escape` 幾行，其餘共用可變狀態；真正的純邏輯早已獨立在 `Core.html`。拆開的風險（載入順序、閉包狀態）大於可讀性的好處。
- 之後某區塊要大改時才順手拆，建議的接縫（共用狀態最少、事件綁定集中）：製作流程（`beginProduction`／`finishProduction`）、原料清單（`renderMaterials`／`addSelection`）、官網價格自動套用與提示詞對話框。
- 拆法：傳統 `<script>` 檔 → 先用 `dom-contract` 與 `client` 測試保護 → 一次只搬一組 → 每次搬移單獨一個提交、不夾帶功能修改 → 搬完立刻 `npm run build` 與全部測試。
- 不得為了拆檔改動 `Core.html` 的對外介面或 `index.html` 的產生流程。
