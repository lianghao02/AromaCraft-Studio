# 精油庫存：持有瓶數

庫存只記錄整數瓶數（0–9999），不計算剩餘 mL，不因加入配方或完成製作自動扣減。設為 0 代表沒有持有，不停用或刪除原料。

## 操作

- 精油卡片的圖示左方顯示瓶數；尚未登錄時顯示 0，不能將預設 0 當成已盤點證明。
- 設定 → 原料與包材 → 點擊精油卡片，在「目前庫存（瓶）」按 −／＋ 或直接輸入，再按「儲存庫存」。
- 庫存獨立儲存，不新增價格批次。「套用」仍管理原料與價格；若庫存欄位有未儲存變動會提醒先儲存。
- 設定頁「匯入精油盤點清單」接受 JSON 陣列，或含 `items` 陣列的 JSON 檔（上限 100 KB、100 項）。每項含 `name`、`materialId`、`count`；可帶 `oilType`（單方／複方／待確認）、`storageGroup` 與 `note` 保留使用者分類及待確認註記；可加 `needsReview: true`，使該列預設不勾選。
- 範例為虛構盤點值：`[{"name":"待核對精油","materialId":"yl-360276","count":2,"needsReview":true}]`。
- 預覽後核對品名、規格及瓶數，再勾選要匯入的列與確認欄。找不到商品時保持未勾選，或明確選擇既有精油；清單可明確指定 `createIfMissing: true`，確認後新增同名精油原料；缺少容量與價格時留空，不猜測規格或翻譯。相同精油重複列須先合併。
- 匯入值是「取代該精油目前持有瓶數」，不是加購瓶數；未選取的商品不變。不允許負數、小數或空白數量。

新增原料與寫入庫存是兩個階段：新增原料成功後才整批儲存瓶數。若中途失敗，已新增的原料保留，錯誤狀態會提示重試；不假稱全數入庫。重複匯入為取代瓶數，不會重複加總。

官方目錄已有的單方／複方分類維持原值；只有尚未分類的新原料，卡片才採用庫存清單的使用者分類。收納分類與待確認事項另外保存，不改官方目錄。

## 儲存與相容性

- 保持 Google Sheets 原有八表與欄位不變，庫存修訂以 `系統設定` 的 `庫存:<materialId>` JSON 紀錄追加。
- `saveInventory` 經同一帳號驗證與寫入鎖，整批先驗證後寫入，提供請求重試去重及版本衝突檢查。讀取舊版資料不需遷移。
- 備份匯出包含庫存修訂；舊資料不會憑空產生既有瓶數。價格、配方及製作成本快照不變。
- 靜態版將庫存操作納入持久化待同步佇列；離線重開保留。不同精油可合併同步，同一精油有版本衝突時保留本機待同步內容並回報，不能把另一台數量直接覆蓋。
- 按下儲存只表示本機／伺服器操作成功；是否同步至家庭雲端以同步狀態為準。真實家庭帳號與 iPhone Safari 仍須實機驗收。
- Apps Script 版需更新來源程式；真實試算表與 Firebase 家庭資料的寫入需登入授權，不能把隔離測試當成正式入庫。

## 照片測試邊界

使用者提供的照片與暫定盤點清單不納入公開原始碼或內建種子資料。照片瓶蓋的暫定品名、容量規格與重複瓶數必須核對，待核對列不可當成正式庫存。

測試使用隔離資料庫；7 項候選商品的勾選、確認與批次寫入流程通過。這不代表照片品名已經由使用者確認，也不代表正式家庭資料已寫入。
